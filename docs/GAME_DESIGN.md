# 狐嗦粤语 — 游戏设计文档 (GAME_DESIGN)

> 本文档定义通用玩法系统。具体关卡设计见 [LEVEL_DESIGN/](./LEVEL_DESIGN/),
> 设计理念见 [DESIGN_PHILOSOPHY.md](./DESIGN_PHILOSOPHY.md)。

## 一、核心体验循环

```
进入关卡 → 经历铺垫链(区域1..N) → 难度挑战 → 句子揭示 → 通关结算 → 解锁下一关
         (跑跳/收集/惊喜)        (操作挑战)   (粤语+发音)  (评价/奖励)
```

爽点分布:
- **即时反馈**:跳跃尘土、金币音效、踩平台弹性、互动光效
- **掌握感**:操作挑战(二段跳+精确跳跃)、buff 强化
- **心理满足**:收集金币、解锁句子、隐藏发现、通关评价
- **惊喜**:三段式叙事(铺垫→揭示→互动)

## 二、平台跳跃系统

### 2.1 操作方式

| 按键 | 动作 | 说明 |
|------|------|------|
| A / ← | 左移 | 持续按住移动 |
| D / → | 右移 | 持续按住移动 |
| W / ↑ / Space | 跳跃 | 支持二段跳 |
| S / ↓ | 蹲下 | 躲避 + 通过低矮通道 |
| E | 互动 | 触发惊喜物件 / 与 NPC 对话 / 揭示句子 |

### 2.2 物理特性(Phaser Arcade Physics)

- 重力加速度
- 平台碰撞检测(上下左右)
- 水平惯性(松手后滑行衰减)
- 二段跳(空中可再跳一次)
- 可碎砖块(踩碎 / 撞碎)

### 2.3 操作手感原则

- **输入即时**:按键响应 <16ms,严禁同步阻塞
- **反馈层级**:输入即时 → 动效反馈(100~300ms)→ 状态反馈(场景级)
- **失败宽容**:掉落回挑战起点,无强惩罚,鼓励重试

## 三、伪图卡片系统(核心组件)

### 3.1 设计理念

用"框 + 文字"代替真实图片。现阶段所有视觉元素(物件/角色/对话/提示)都用伪图卡片。
后期替换真图时,只改资源路径,不改逻辑。详见 [DESIGN_PHILOSOPHY.md 原则5](./DESIGN_PHILOSOPHY.md)。

### 3.2 卡片属性

| 属性 | 类型 | 说明 |
|------|------|------|
| type | enum | character / object / scenery / dialogue / hint / result |
| text | string | 主文字(必填,如"大石头") |
| subtitle | string | 副文字(可选,如"可以踢一脚") |
| suffix | enum | `.jpg`(静态) / `.gif`(文字循环滚动) / 无 |
| textColor | color | 文字颜色 |
| borderColor | color | 边框颜色 |
| borderWidth | int | 边框粗细 |
| bgColor | color | 背景色(支持高亮) |
| width / height | int | 尺寸 |
| scale | float | 缩放 |
| scrollSpeed | int | `.gif` 文字滚动速度(字符/秒) |
| highlight | bool | 是否高亮(用于强调) |

### 3.3 类型样式约定

| 类型 | 边框色 | 说明 |
|------|--------|------|
| character | 橙色 | NPC / 主角立绘 |
| object | 蓝色 | 可互动物件 |
| scenery | 灰色 | 背景物件 |
| dialogue | 棕色 | 对话框 |
| hint | 黄色 | 全局提示 |
| result | 金色 | 结算卡片 |

### 3.4 后缀语义

- `.jpg`:静态展示,文字居中
- `.gif`:文字在卡片内**循环滚动**显示(会心一笑的梗)
  - 例:"我系咸鱼...我系咸鱼..."无限滚动
  - 例:"加班到凌晨三点半...好累啊..."滚动

### 3.5 全局复用

伪图卡片系统服务于:
- 场景物件(咸鱼 / 石头 / 路标 / 砖块)
- 角色立绘(NPC / 主角 / 惊喜梗角色)
- 对话卡片(NPC 对话 / 选择框)
- 提示卡片(全局提示 / 互动提示)
- 结算卡片(通关结算 / 评价)

### 3.6 状态驱动卡片（v0.2 新增）

卡片可以绑定一个"状态文字源"（StateTextSource），根据游戏对象（Player/MovableNpc）的实时状态自动切换显示文字。

**接口**：
```typescript
interface StateTextSource {
  getState(): string  // 返回当前状态标识，如 'run' / 'jump' / 'flee' / 'caught'
}
```

**绑定方式**：
- TextSprite 新增 `bindState(source, textMap)` 方法
- `textMap` 是状态→文字的映射表，写在关卡 JSON 的 `stateBinding` 字段中
- 不绑定则维持静态文字（向后兼容，现有卡片零影响）

**典型场景**：
- 追捕小游戏中，Player 卡片显示"追/跳/跑"，MovableNpc 卡片显示"逃/躲/被抓"
- 打架场景中，双方卡片实时显示"出左腿/踢右拳/格挡"
- 挑战中，平台卡片根据踩踏状态显示"站稳/快碎了"

**性能**：状态变化时才 `setText`，避免每帧重绘。

**扩展性**：未来可扩展为"状态→样式"映射（如受伤变红边框），只需扩展映射表结构。

### 3.7 扩展接口

预留扩展能力,后期可加:
- 动画类型(淡入/弹出/抖动/呼吸)
- 特效(粒子/光晕/拖尾)
- 交互响应(悬停/点击反馈)
- 真图替换(资源路径加载真实图片)
- 状态驱动显示（已实现 v0.2）

## 四、铺垫链系统(核心创新)

### 4.1 结构

```
区域1(碎片1) → 区域2(碎片2) → ... → 区域N(碎片N) → 挑战区 → 揭示区
```

每个区域铺一个"碎片",碎片类型:
- **场景碎片**:伪图卡片物件(咸鱼/足球/寺庙)
- **对话碎片**:NPC 对话关键词(梦想/打工)
- **视觉碎片**:涂鸦/路标/背景元素

### 4.2 碎片归位判别

揭示句子时,玩家脑中是否已具备理解这句台词的所有关键词?
- 是 → 铺垫链成立
- 否 → 需要补碎片

### 4.3 对话语言规则

- 铺垫链全程:**普通话对话**
- 最终揭示的句子:**粤语原版 + 粤拼 + 普通话释义 + 发音**
- 理由:让粤语成为"揭示时刻",而非全程认知负担

## 五、惊喜事件系统

### 5.1 三段式叙事

| 阶段 | 作用 | 手法 | 示例 |
|------|------|------|------|
| 铺垫 | 建立预期 | 全局提示卡片预告 | "3秒后会出现一个帅哥" |
| 揭示 | 认知共鸣 | 伪图卡片显示角色 + 文字滚动 | "叶问.gif" 滚动"我要打十个" |
| 互动 | 惊喜转玩法 | 对话转化为指引/buff/解锁 | 叶问指引地铁站方向 |

### 5.2 惊喜来源(类型要宽)

- 文化梗(孙悟空 / 叶问 / 周星驰角色)
- 网络热梗
- 谐音梗
- 粤语本地文化符号
- **优先选大众共鸣最强的**

### 5.3 惊喜事件分类

| 类型 | 触发方式 | 数量 | 说明 |
|------|---------|------|------|
| 必触发惊喜 | 主线必经之路 | 每关1个 | 核心剧情,给 buff |
| 隐藏惊喜 | 探索发现 | 每关1-2个 | 额外奖励,鼓励探索 |

### 5.4 反向引导机制

伪图卡片的文字提示是可互动的引导信号:
- 负面提示("别碰""禁止")激发探索
- 玩家碰了必有反馈(奖励为主,弱惩罚)
- "反骨探索"成为乐趣来源

## 六、Buff 系统

### 6.1 Buff 来源

惊喜事件互动后获得,持续到通关。

### 6.2 Buff 类型

| Buff | 来源 | 效果 |
|------|------|------|
| 咸鱼翻身 | 咸鱼打工关·必触发惊喜 | 二段跳高度+30%,滞空更久 |
| 火眼金睛 | (预留)水果摊关·必触发惊喜 | 高亮隐藏金币路径 |

### 6.3 Buff 设计原则

- 操作向优先(增强掌握感)
- 视觉反馈明显(玩家感知到变强)
- 降低后续挑战难度,但不消除挑战

## 八、探索指引系统(四层渐进)

| 层级 | 方式 | 作用 | 实现成本 |
|------|------|------|---------|
| L1 视觉锚点 | 目标 emoji 始终发光 + 屏幕边缘箭头指示方向 | 玩家永远知道大方向 | 低 |
| L2 面包屑 | 金币沿主路径散布 | 玩家自然跟路走 | 低 |
| L3 NPC 提示 | 开场 NPC 一句话给方向 | 建立动机+方向 | 中 |
| L4 惊喜引导 | 可互动物件轻微抖动/光效,靠近显示"按 E" | 鼓励探索但不强求 | 低 |

**原则**:L1+L2 保证主线不卡,L3+L4 鼓励支线探索。玩家可只走主线通关,但探索有额外奖励。

## 九、子场景系统（v0.2 新增）

### 9.1 设计理念

借鉴马里奥"进入管道切换场景"的经典设计。主世界承载跑跳收集，保持流畅；关键剧情点（NPC 对话/惊喜事件）切入独立子场景，展开更丰富的剧情和玩法。

### 9.2 子场景类型

| 类型 | 说明 | 示例 |
|------|------|------|
| `chase` | 追捕小游戏 | 老伯逃跑，玩家追，碰到即抓住 |
| `dialogue` | 纯剧情对话展开 | 星爷长篇对话，切换视角 |
| `fight` | 打架/对决 | 与 NPC 对打，动作状态实时显示 |

### 9.3 生命周期

```
主世界 LevelScene
  ├─ scene.pause()          ← 触发子场景时暂停主世界
  ├─ scene.launch('SubScene', config)  ← 启动子场景
  │
  ├─ [子场景运行中，玩家完全在子场景中操作]
  │
  ├─ 子场景结束 → eventBus.emit('subscene-complete', result)
  ├─ scene.stop('SubScene')  ← 销毁子场景
  └─ scene.resume()          ← 恢复主世界，应用子场景结果
```

### 9.4 触发条件

| 触发方式 | 说明 |
|---------|------|
| 进入区域 | 玩家踏入某个 Zone，自动触发 |
| NPC 对话 | 与 NPC 对话到第 N 句时触发 |
| 互动物件 | 按 E 互动后触发 |

### 9.5 结果回传

子场景结束时通过 `eventBus` 回传结果：
- `giveBuff`: 给玩家 Buff
- `unlockPath`: 解锁新路径
- `revealCoins`: 揭示隐藏金币
- `advanceStory`: 推进主线剧情

## 十、NPC AI 与追捕系统（v0.2 新增）

### 10.1 MovableNpc 设计

当前 `Npc` 是静态物理体（固定在原地）。新增 `MovableNpc` 子类，拥有动态物理体和 AI 状态机。

**AI 状态机**：
```
idle → patrol → flee → caught → idle
         ↑                 ↓
         └─── 巡逻路径 ────┘
```

| 状态 | 行为 | 触发条件 |
|------|------|---------|
| `idle` | 静止不动 | 初始状态 / 玩家远离 |
| `patrol` | 在巡逻点间移动 | 玩家靠近但未触发追逐 |
| `flee` | 远离玩家方向跑 | 玩家进入触发范围 |
| `caught` | 停止，触发被抓事件 | 玩家碰到 NPC |

### 10.2 追捕机制

**追捕小游戏**（ChaseScene 子场景）：
- 独立场景，有自己的平台布局（阶梯块）
- 老伯（MovableNpc）自动逃跑，沿预设路径移动
- 玩家控制阿粤追，复用 Player 物理系统
- `physics.add.overlap(player, npc)` 判定"抓到"
- 抓到后：老伯给出指引对话 → 子场景结束 → 回传结果

**可配置参数**：
- 逃跑速度、巡逻路径点
- 限时（可选，超时失败重试）
- 成功奖励：金币/指引/Buff
- 失败：无惩罚，可重试

### 10.3 状态驱动集成

追捕过程中，双方卡片通过状态驱动实时显示动作：
- Player: "追" / "跳" / "跑"
- MovableNpc: "逃" / "躲" / "啊！"

## 十一、区域模块化（v0.2 新增）

### 11.1 设计理念

将关卡从"扁平列表"（platforms/coins/npcs 平铺）升级为"区域分组"（zones[]），每个区域可独立配置子场景、引导文字、专属玩法。

### 11.2 区域结构

```typescript
interface ZoneData {
  id: string                    // 'zone_1_oldman'
  name: string                  // '打工区'
  bounds: { x, y, w, h }       // 区域边界
  platforms: PlatformData[]     // 区域内平台
  coins: CoinData[]             // 区域内金币
  npcs: NpcData[]               // 区域内 NPC
  interactables: InteractableData[] // 区域内可互动物件
  cutsceneId?: string           // 进入时触发的子场景ID
  enterHint?: string            // 进入时显示的引导文字
  checkpointId?: string         // 检查点ID（掉落复活点）
}
```

### 11.3 向后兼容

现有 `LevelData` 的 `platforms/coins/npcs` 字段保留作为 fallback（无 zones 时的全量数据）。有 `zones` 时优先使用 zones。

### 11.4 登台门槛（集齐汉字）

揭示平台（revealZone）增加金币门槛：
- `requireCoins`: 需要集齐的汉字数量
- 金币不足时：提示"还需收集 X 个汉字"，不触发揭示
- 金币足够时：正常揭示

**设计意图**：给收集系统赋予意义——每个金币是一个汉字，集齐所有汉字才能"拼出"最终粤语句子。

## 十二、音效系统（v0.2 新增）

### 12.1 设计原则

- Web Audio API 合成，零外部依赖
- 关键时机必有反馈，但不喧宾夺主
- 音量统一管理，可静音

### 12.2 音效清单

| 音效 | 触发时机 | 合成方式 |
|------|---------|---------|
| sfx_jump | 跳跃 | 短促高频正弦波 |
| sfx_doubleJump | 二段跳 | 短促上扬频率 |
| sfx_coin | 金币拾取 | 清脆短音 |
| sfx_interact | 互动(E) | 中频点击音 |
| sfx_surprise | 惊喜触发 | 爆开特效音 |
| sfx_brickBreak | 砖块碎裂 | 噪音衰减 |
| sfx_levelComplete | 通关 | 上扬和弦 |
| sfx_hit | 受伤/被碰到 | 低频短音 |
| sfx_chase_start | 追捕开始 | 紧张短音 |

### 12.3 实现方式

`SfxManager` 类（单例），管理 AudioContext 和音效合成。各场景按需调用 `sfxManager.play('jump')`。与发音引擎共用 AudioContext。

## 十三、检查点与复活系统（v0.2 新增）

### 13.1 设计理念

失败宽容原则（DESIGN_PHILOSOPHY 原则2）：掉落回当前区域起点，无强惩罚，鼓励重试。

### 13.2 检查点设置

- 每个区域的入口自动设为检查点
- 玩家踏入新区域时自动保存检查点
- 掉落死亡/被敌人碰到 → 回到最近检查点

### 13.3 复活流程

1. 玩家死亡（掉落世界底部 / 被敌人碰到）
2. 关闭当前对话/子场景（如果有）
3. 玩家回到最近检查点
4. Toast 提示（如"回到了打工区"）
5. 已收集的金币保留（不重置）

## 十五、发音引擎

### 15.1 设计原则

- **策略模式**:统一接口,运行时切换
- **渐进式**:当前用 Jyutping 方案,后续可无缝切换
- **降级机制**:首选方案失败时自动降级

### 15.2 三种方案

| 方案 | 类名 | 原理 | 粤语质量 | 依赖 | 状态 |
|------|------|------|---------|------|------|
| 粤拼合成 | JyutpingSpeaker | 基于粤拼音素映射 + Web Audio API | 中 | 无 | **当前启用** |
| Web Speech | WebSpeechSpeaker | 浏览器原生 SpeechSynthesis | 低 | 浏览器支持 | 预留 |
| 豆包 TTS | DoubaoTTSSpeaker | 豆包大模型 TTS API | 高 | API Key | 预留 |

### 15.3 统一接口

```typescript
interface BaseSpeaker {
  speak(text: string, options?: SpeakOptions): Promise<void>;      // 朗读文本
  speakJyutping(jp: string, options?: SpeakOptions): Promise<void>; // 朗读粤拼
  stop(): void;                                                       // 停止播放
  isAvailable(): boolean;                                             // 是否可用
}
```

## 十六、角色设计

### 16.1 主角:阿粤

- 形象:橙色小狐狸,围着红色围巾(现阶段用伪图卡片"阿粤.jpg"代替)
- 性格:调皮、好奇、爱"胡说"
- 动画:跑动、跳跃、蹲下、互动、受伤(用伪图卡片 `.gif` 滚动表达状态)

### 16.2 NPC 类型

| NPC | 伪图卡片 | 功能 | 出现场景 |
|-----|---------|------|---------|
| 路边老伯 | "老伯.jpg" | 开场指引 / 通关埋伏笔（可追捕） | 关卡起终点 |
| 关卡主题 NPC | 如"星爷.jpg" | 铺垫链关键对话 | 关卡中段 |
| 惊喜梗角色 | 如"叶问.gif" | 惊喜事件触发 | 隐藏/必触发点 |

### 16.3 MovableNpc（v0.2 新增）

可移动 NPC，继承 Npc，增加动态物理体和 AI 状态机。用于追捕/打架等子场景。

| 属性 | 说明 |
|------|------|
| 物理体 | 动态 Arcade Body（非静态） |
| AI 状态 | idle / patrol / flee / caught |
| 状态驱动 | 实现 StateTextSource，卡片实时显示动作 |
| 配置数据 | 巡逻路径点、逃跑速度、触发半径 |

## 十七、通关结算

### 17.1 结算内容

- 句子解锁 ✓(粤语句子 + 粤拼 + 释义)
- 金币数
- 隐藏发现数(X/Y)
- 通关评价(根据金币数)

### 17.2 评价等级

| 评价 | 条件 | 说明 |
|------|------|------|
| 咸鱼翻身 | 通关即可 | 基础通关 |
| 咸鱼之王 | 金币数 ≥ 50% | 收集过半 |
| 梦想家 | 金币数 100% + 隐藏全发现 | 完美通关 |

### 17.3 伏笔机制

通关后老伯出现,埋下一关伏笔(如"下次带你去水果摊")。
