## 一、核心体验循环

```
进入关卡 → 经历铺垫链(区域1..N) → 难度挑战 → 句子揭示 → 通关结算 → 解锁下一关
         (跑跳/收集/惊喜)        (操作挑战)   (粤语+发音)  (评价/奖励)
```

爽点分布:
- **即时反馈**:跳跃尘土、金币音效、踩平台弹性、互动光效
- **掌握感**:操作挑战(二段跳+精确跳跃)、buff 强化
- **心理满足**:收集金币、解锁句子、隐藏发现、通关评价
- **惊喜**:三段式叙事(铺垫→揭示→互动)

## 二、平台跳跃系统

### 2.1 操作方式

| 按键 | 动作 | 说明 |
|------|------|------|
| A / ← | 左移 | 持续按住移动 |
| D / → | 右移 | 持续按住移动 |
| W / ↑ / Space | 跳跃 | 支持二段跳 |
| S / ↓ | 蹲下 | 躲避 + 通过低矮通道 |
| E | 互动 | 触发惊喜物件 / 与 NPC 对话 / 揭示句子 |

### 2.2 物理特性(Phaser Arcade Physics)

- 重力加速度
- 平台碰撞检测(上下左右)
- 水平惯性(松手后滑行衰减)
- 二段跳(空中可再跳一次)
- 可碎砖块(踩碎 / 撞碎)

### 2.3 操作手感原则

- **输入即时**:按键响应 <16ms,严禁同步阻塞
- **反馈层级**:输入即时 → 动效反馈(100~300ms)→ 状态反馈(场景级)
- **失败宽容**:掉落回挑战起点,无强惩罚,鼓励重试

## 三、伪图卡片系统(核心组件)

### 3.1 设计理念

用"框 + 文字"代替真实图片。现阶段所有视觉元素(物件/角色/对话/提示)都用伪图卡片。
后期替换真图时,只改资源路径,不改逻辑。详见 [DESIGN_PHILOSOPHY.md 原则5](./DESIGN_PHILOSOPHY.md)。

### 3.2 卡片属性

| 属性 | 类型 | 说明 |
|------|------|------|
| type | enum | character / object / scenery / dialogue / hint / result |
| text | string | 主文字(必填,如"大石头") |
| subtitle | string | 副文字(可选,如"可以踢一脚") |
| suffix | enum | `.jpg`(静态) / `.gif`(文字循环滚动) / 无 |
| textColor | color | 文字颜色 |
| borderColor | color | 边框颜色 |
| borderWidth | int | 边框粗细 |
| bgColor | color | 背景色(支持高亮) |
| width / height | int | 尺寸 |
| scale | float | 缩放 |
| scrollSpeed | int | `.gif` 文字滚动速度(字符/秒) |
| highlight | bool | 是否高亮(用于强调) |

### 3.3 类型样式约定

| 类型 | 边框色 | 说明 |
|------|--------|------|
| character | 橙色 | NPC / 主角立绘 |
| object | 蓝色 | 可互动物件 |
| scenery | 灰色 | 背景物件 |
| dialogue | 棕色 | 对话框 |
| hint | 黄色 | 全局提示 |
| result | 金色 | 结算卡片 |

### 3.4 后缀语义

- `.jpg`:静态展示,文字居中
- `.gif`:文字在卡片内**循环滚动**显示(会心一笑的梗)
  - 例:"我系咸鱼...我系咸鱼..."无限滚动
  - 例:"加班到凌晨三点半...好累啊..."滚动

### 3.5 全局复用

伪图卡片系统服务于:
- 场景物件(咸鱼 / 石头 / 路标 / 砖块)
- 角色立绘(NPC / 主角 / 惊喜梗角色)
- 对话卡片(NPC 对话 / 选择框)
- 提示卡片(全局提示 / 互动提示)
- 结算卡片(通关结算 / 评价)

### 3.6 状态驱动卡片（v0.2 新增）

卡片可以绑定一个"状态文字源"（StateTextSource），根据游戏对象（Player/MovableNpc）的实时状态自动切换显示文字。

**接口**：
```typescript
interface StateTextSource {
  getState(): string  // 返回当前状态标识，如 'run' / 'jump' / 'flee' / 'caught'
}
```

**绑定方式**：
- TextSprite 新增 `bindState(source, textMap)` 方法
- `textMap` 是状态→文字的映射表，写在关卡 JSON 的 `stateBinding` 字段中
- 不绑定则维持静态文字（向后兼容，现有卡片零影响）

**典型场景**：
- 追捕小游戏中，Player 卡片显示"追/跳/跑"，MovableNpc 卡片显示"逃/躲/被抓"
- 打架场景中，双方卡片实时显示"出左腿/踢右拳/格挡"
- 挑战中，平台卡片根据踩踏状态显示"站稳/快碎了"

**性能**：状态变化时才 `setText`，避免每帧重绘。

**扩展性**：未来可扩展为"状态→样式"映射（如受伤变红边框），只需扩展映射表结构。

### 3.7 扩展接口

预留扩展能力,后期可加:
- 动画类型(淡入/弹出/抖动/呼吸)
- 特效(粒子/光晕/拖尾)
- 交互响应(悬停/点击反馈)
- 真图替换(资源路径加载真实图片)
- 状态驱动显示（已实现 v0.2）

## 四、铺垫链系统(核心创新)

### 4.1 结构

```
区域1(碎片1) → 区域2(碎片2) → ... → 区域N(碎片N) → 挑战区 → 揭示区
```

每个区域铺一个"碎片",碎片类型:
- **场景碎片**:伪图卡片物件(咸鱼/足球/寺庙)
- **对话碎片**:NPC 对话关键词(梦想/打工)
- **视觉碎片**:涂鸦/路标/背景元素

### 4.2 碎片归位判别

揭示句子时,玩家脑中是否已具备理解这句台词的所有关键词?
- 是 → 铺垫链成立
- 否 → 需要补碎片

### 4.3 对话语言规则

- 铺垫链全程:**普通话对话**
- 最终揭示的句子:**粤语原版 + 粤拼 + 普通话释义 + 发音**
- 理由:让粤语成为"揭示时刻",而非全程认知负担

## 五、惊喜事件系统

### 5.1 三段式叙事

| 阶段 | 作用 | 手法 | 示例 |
|------|------|------|------|
| 铺垫 | 建立预期 | 全局提示卡片预告 | "3秒后会出现一个帅哥" |
| 揭示 | 认知共鸣 | 伪图卡片显示角色 + 文字滚动 | "叶问.gif" 滚动"我要打十个" |
| 互动 | 惊喜转玩法 | 对话转化为指引/buff/解锁 | 叶问指引地铁站方向 |

### 5.2 惊喜来源(类型要宽)

- 文化梗(孙悟空 / 叶问 / 周星驰角色)
- 网络热梗
- 谐音梗
- 粤语本地文化符号
- **优先选大众共鸣最强的**

### 5.3 惊喜事件分类

| 类型 | 触发方式 | 数量 | 说明 |
|------|---------|------|------|
| 必触发惊喜 | 主线必经之路 | 每关1个 | 核心剧情,给 buff |
| 隐藏惊喜 | 探索发现 | 每关1-2个 | 额外奖励,鼓励探索 |

### 5.4 反向引导机制

伪图卡片的文字提示是可互动的引导信号:
- 负面提示("别碰""禁止")激发探索
- 玩家碰了必有反馈(奖励为主,弱惩罚)
- "反骨探索"成为乐趣来源

## 六、Buff 系统

### 6.1 Buff 来源

惊喜事件互动后获得,持续到通关。

### 6.2 Buff 类型

| Buff | 来源 | 效果 |
|------|------|------|
| 咸鱼翻身 | 咸鱼打工关·必触发惊喜 | 二段跳高度+30%,滞空更久 |
| 火眼金睛 | (预留)水果摊关·必触发惊喜 | 高亮隐藏金币路径 |

### 6.3 Buff 设计原则

- 操作向优先(增强掌握感)
- 视觉反馈明显(玩家感知到变强)
- 降低后续挑战难度,但不消除挑战

## 八、探索指引系统(四层渐进)

| 层级 | 方式 | 作用 | 实现成本 |
|------|------|------|---------|
| L1 视觉锚点 | 目标 emoji 始终发光 + 屏幕边缘箭头指示方向 | 玩家永远知道大方向 | 低 |
| L2 面包屑 | 金币沿主路径散布 | 玩家自然跟路走 | 低 |
| L3 NPC 提示 | 开场 NPC 一句话给方向 | 建立动机+方向 | 中 |
| L4 惊喜引导 | 可互动物件轻微抖动/光效,靠近显示"按 E" | 鼓励探索但不强求 | 低 |

**原则**:L1+L2 保证主线不卡,L3+L4 鼓励支线探索。玩家可只走主线通关,但探索有额外奖励。

## 九、子场景系统（v0.2 新增）

### 9.1 设计理念

借鉴马里奥"进入管道切换场景"的经典设计。主世界承载跑跳收集，保持流畅；关键剧情点（NPC 对话/惊喜事件）切入独立子场景，展开更丰富的剧情和玩法。

### 9.2 子场景类型

| 类型 | 说明 | 示例 |
|------|------|------|
| `chase` | 追捕小游戏 | 老伯逃跑，玩家追，碰到即抓住 |
| `findDifference` | 找区别 | 在一堆咸鱼中找出梦想鱼，限时眼力挑战 |
| `dialogue` | 纯剧情对话展开 | 星爷长篇对话，切换视角 |
| `fight` | 打架/对决 | 与 NPC 对打，动作状态实时显示 |

### 9.3 生命周期

```
主世界 LevelScene
  ├─ scene.pause()          ← 触发子场景时暂停主世界
  ├─ scene.launch('SubScene', config)  ← 启动子场景
  │
  ├─ [子场景运行中，玩家完全在子场景中操作]
  │
  ├─ 子场景结束 → eventBus.emit('subscene-complete', result)
  ├─ scene.stop('SubScene')  ← 销毁子场景
  └─ scene.resume()          ← 恢复主世界，应用子场景结果
```

### 9.4 触发条件

| 触发方式 | 说明 |
|---------|------|
| 进入区域 | 玩家踏入某个 Zone，自动触发 |
| NPC 对话 | 与 NPC 对话到第 N 句时触发 |
| 互动物件 | 按 E 互动后触发 |

### 9.5 结果回传

子场景结束时通过 `eventBus` 回传结果：
- `giveBuff`: 给玩家 Buff
- `unlockPath`: 解锁新路径
- `revealCoins`: 揭示隐藏金币
- `advanceStory`: 推进主线剧情

### 9.6 FindDifference 子场景：「找区别」（v0.5 新增）

#### 9.6.1 设计理念

子场景2 的核心问题是：「在一堆咸鱼中找出梦想鱼」。

主题隐喻：**「做人如果没梦想，跟咸鱼有何区别」——在平庸的咸鱼群中，梦想鱼（有梦想的人）会脱颖而出，闪闪发光。** 玩家需要在限时压力下，用眼力辨别出那条"不一样的鱼"。

与子场景1（追捕/速度型考验操作）形成差异化——子场景2 考验眼力、反应和抗压能力。

#### 9.6.2 核心设定

**角色定义**：
| 角色 | 视觉特征 | 隐喻 |
|------|---------|------|
| 梦想鱼（目标鱼） | 颜色鲜艳（橙/金色）、有光晕、眼睛有神（(◕‿◕)） | 有梦想的人 |
| 咸鱼（干扰项） | 灰暗/干瘪、眼神死（(´；ω；`)）、无光晕 | 没梦想的人 |

**基本规则**：
- 8-20 条鱼排列成网格
- 其中 1 条是梦想鱼，其余是咸鱼
- 玩家点击梦想鱼 → 得分，换一批新的
- 每轮限时 3-5 秒，难度递增
- 共 5-8 轮，统计总分

#### 9.6.3 紧迫感机制（核心设计）

为避免"静态找不同"的单调感，叠加以下多层紧迫感机制：

| 维度 | 机制 | 说明 |
|------|------|------|
| **时间压力** | 倒计时进度条 | 每轮 3-5 秒，进度条燃烧/收缩动画，最后 1 秒心跳加速音效 |
| **干扰升级** | 鱼轻微晃动/游动 | 难度递增时晃动幅度加大，制造视觉干扰 |
| **连击系统** | 连续正确点击 → combo | combo 越高分数倍率越高（x1/x1.5/x2），断了 combo 有失落感 |
| **错误惩罚** | 点错咸鱼 → 扣时间 | 短暂屏幕震动 + 扣 0.5s，增加紧张感 |
| **Boss 轮** | 最后一轮特殊玩法 | 梦想鱼在鱼群中快速穿梭移动，玩家要在移动中点击它 |
| **音效设计** | 分层音效反馈 | 倒计时心跳音、combo 音效（音调递增）、错误震动音、成功清脆音 |

#### 9.6.4 难度递增曲线

| 轮次 | 鱼数量 | 区别度 | 限时 | 额外干扰 |
|------|--------|--------|------|---------|
| 1 | 8 | 高（梦想鱼明显鲜艳） | 5s | 无 |
| 2 | 10 | 高 | 5s | 无 |
| 3 | 12 | 中（颜色差异缩小） | 4s | 轻微晃动 |
| 4 | 14 | 中 | 4s | 晃动 |
| 5 | 16 | 低（差异微妙） | 3s | 晃动+位移 |
| 6 | 18 | 低 | 3s | 晃动+位移 |
| 7 | 20 | 极低 | 3s | 晃动+位移+旋转 |
| 8 (Boss) | 16 | 中 | 4s | 梦想鱼快速移动 |

#### 9.6.5 计分规则

```
基础分 = 100 分/轮
combo 倍率 = 1 + (combo数 - 1) × 0.5（最高 x3）
剩余时间奖励 = 剩余秒数 × 20 分
错误惩罚 = -50 分/次

总分 = Σ(基础分 × combo倍率 + 时间奖励 - 错误扣分)
```

三档评价：
- ≥ 80% 满分 → 「火眼金睛」
- ≥ 50% 满分 → 「咸鱼观察家」
- < 50% 满分 → 「还需修炼」

#### 9.6.6 技术实现要点

- 鱼卡片使用 `TextSprite`（伪图卡片系统），统一圆角 + 边框风格
- 鱼卡片尺寸：约 80×80（内部分辨率），网格间距自适应
- 梦想鱼使用 `highlight: true` + `glow` 动效，颜色从 `COLORS` 中取橙色/金色
- 咸鱼使用灰色调 + 无动效，文字显示颜文字如 `(´；ω；`)`
- 晃动/位移使用 Phaser `tweens`，不依赖物理引擎
- 倒计时使用 `scene.time.delayedCall` + 进度条 Graphics 绘制
- 音效走 `SfxManager` 统一接口
- 结果回传：`complete({ outcome: 'success', rewards: { word, jyutping } })`

#### 9.6.7 方案对比与决策

| 维度 | 方案1: 眼力找茬（推荐） | 方案2: 梦想鱼消消乐 |
|------|----------------------|-------------------|
| 核心玩法 | 限时点击辨别 | 交换相邻 tile 消除 |
| 开发量 | 低（~300行） | 高（~800行+） |
| 紧迫感 | 倒计时+combo+干扰 | 步数限制 |
| 主题契合 | 梦想脱颖而出 | 梦想感染他人 |
| 风险 | 低 | 开发量大，节奏难控制 |
| 与子场景1差异 | 眼力 vs 操作 | 策略 vs 操作 |

**决策**: 采用方案1「眼力找茬」。方案2 保留为未来扩展选项。

**理由**:
- 符合"小步快跑"迭代节奏
- 核心玩法简单直接，叠加紧迫感机制后不单调
- 与子场景1（追逐/操作型）形成互补——一个考操作，一个考眼力
- 方案2 的"梦想感染他人"隐喻很好，但开发量过大，适合作为后续版本的内容深化

#### 9.6.9 增加难度的思路

> **状态说明**：方案一、三已实现；方案二保留备用，待后续迭代。

##### 一、低成本高收益（✅ 已实现）

| 方案 | 说明 | 难度提升 |
|------|------|----------|
| **保证初始距离** | 初始光标放在离梦想鱼最远的鱼上，确保开局至少有几秒追捕时间 | ★★ |
| **增加鱼数量** | 20 → 45 条，鱼越多，"就近选中"越容易选到非目标鱼，大方向导航失效 | ★★★ |
| **缩小导航角度** | ±45° → ±25°，方向键必须更精准，稍微偏一点就选不到想选的鱼 | ★★★ |
| **逃跑方向加随机** | 梦想鱼躲避方向加 ±30° 随机偏移（已替换为高亮干扰 AI） | ★★ |

##### 二、AI 行为升级（📋 保留备用）

| 方案 | 说明 | 难度提升 |
|------|------|----------|
| **梦想鱼混入鱼群** | 梦想鱼主动向最近的鱼靠拢（"躲进鱼群"），利用其他鱼做掩护 | ★★★ |
| **假动作** | 逃跑时先向一个方向虚晃，再突然折返，让玩家追错方向 | ★★★★ |
| **扩大逃跑半径** | 250px → 350px，梦想鱼更早察觉危险，有更多逃跑空间 | ★★ |

##### 三、操作干扰（✅ 已实现）

| 方案 | 说明 | 难度提升 |
|------|------|----------|

- 高亮干扰 AI：光标靠近梦想鱼（250px 内）时，选中高亮 500ms 闪烁 + 弱化透明度（填充 0.05 / 边框 0.3），替代逃跑 AI

- 速度可调节：基准时长可配置，实际速度在 ±30% 范围内浮动

## 十、NPC AI 与追捕系统（v0.2 新增）

### 10.1 MovableNpc 设计

当前 `Npc` 是静态物理体（固定在原地）。新增 `MovableNpc` 子类，拥有动态物理体和 AI 状态机。

**AI 状态机**：
```
idle → patrol → flee → caught → idle
         ↑                 ↓
         └─── 巡逻路径 ────┘
```

| 状态 | 行为 | 触发条件 |
|------|------|---------|
| `idle` | 静止不动 | 初始状态 / 玩家远离 |
| `patrol` | 在巡逻点间移动 | 玩家靠近但未触发追逐 |
| `flee` | 远离玩家方向跑 | 玩家进入触发范围 |
| `caught` | 停止，触发被抓事件 | 玩家碰到 NPC |

### 10.2 追捕机制

**追捕小游戏**（ChaseScene 子场景）：
- 独立场景，有自己的平台布局（阶梯块 + 墙壁）
- 老伯（MovableNpc）自动逃跑，沿预设路径移动
- 玩家控制阿粤追，复用 Player 物理系统
- `physics.add.overlap(player, npc)` 判定"抓到"
- 抓到后：老伯给出指引对话 → 子场景结束 → 回传结果

**可配置参数**：
- 逃跑速度、巡逻路径点
- 限时（可选，超时失败重试）
- 成功奖励：金币/指引/Buff
- 失败：无惩罚，可重试

### 10.3 追捕难度升级（v0.3 新增）

**双倍速度**：
- 进入追捕子场景后，Player 最大速度翻倍（`PHYSICS.PLAYER_SPEED * 2`）
- NPC 逃跑速度翻倍（`fleeSpeed * 2`）
- 场景结束时恢复（Player 重新创建，无需手动恢复）

**NPC 子弹系统**：
- NPC 可配置子弹数量（默认 5 发）、射击范围（默认 100px）、冷却时间（默认 500ms）
- 触发条件：玩家距离 NPC < 射击范围，且 NPC 处于 `flee` 状态，有剩余子弹，冷却完毕
- 子弹：`Bullet` 类，继承 `TextSprite` 基础卡片，20x20 蓝色"弹"字，动态物理体
- 子弹以 400px/s 速度飞向玩家，生命周期 3 秒自动销毁
- 碰世界边界/平台后销毁
- 命中玩家：推飞玩家（水平 600px/s + 上抛 -400px/s），子弹销毁
- 用完子弹后 NPC 卡片显示"弹尽!"（`flee_empty` 状态），但继续以双倍速度逃跑

**多阶梯平台 + 墙壁反弹**：
- 场景布局从 JSON 配置驱动（`chaseScene.platforms`），支持多层阶梯 + 垂直墙壁
- 平台反弹系数（`platformBounce`，默认 0.6）：玩家/NPC 水平碰撞平台边缘时反弹
- 垂直无反弹（避免地面弹跳影响手感）
- 墙壁反弹增加追逐混乱度和不可预测性

**NPC 主动跳跃**：
- 玩家在 NPC 上方（高于 50px）且 NPC 着地 → 主动跳跃（-480 速度）
- NPC 被障碍物阻挡（blocked.left/right）→ 跳跃（-420 速度）
- 增强 NPC 逃脱能力，追捕不再单调

## 十八、慢动作系统（v0.4 新增）

### 18.1 设计理念

借鉴电影慢动作效果，通过 `physics.world.timeScale` 控制全局物理速度，配合雨天场景作为视觉载体，实现画面冻结、慢放、恢复等电影级效果。

**分步迭代策略**：
- **第一步**（已完成）：建立 SlowMoManager + RainManager 独立模块，通过临时按钮手动切换慢放，验证核心机制
- **第二步**（已完成）：接入追捕场景，自动触发子弹时间序列（多维度距离门控 + 轨迹预测）
- **第三步**（当前）：触发距离调优 + 预测轨迹可视化

### 18.2 子弹时间自动触发（ChaseScene）

**核心思路**：当玩家跳跃接近逃跑者、且轨迹预测显示两者将交汇时，自动触发慢动作序列。

**两段式序列**：
```
预测交汇 → 冻结1s(NPC闪现逃逸+0.9→0.1倒计时) → 慢放3s(20%速度) → 恢复全速
```

**触发条件**：玩家必须在空中（`isAirborne`），且视线无遮挡（`hasClearLineOfSight`），然后通过以下多级门控判断。

**多维度距离门控（L1-L8）** — 所有像素阈值为 `collisionDist × 系数`（cd ≈ 45px）：

| 级别 | 触发条件 | ~像素值 | 说明 |
|------|---------|--------|------|
| L1 | `dist < 2.2×cd` | ~100px | 斜线贴近，综合距离最近 |
| L2 | `dx < 1.8×cd && dy < 2.2×cd` | ~80/100px | 横向贴近 + 垂直不乱 |
| L3 | `dy < 1.8×cd && dx < 2.2×cd` | ~80/100px | 纵向贴近 + 水平不乱 |
| L4 | `dist < cd + 10px` | ~55px | 兜底保险，必定闪现救场 |
| L5 | `minDist < 0.33×cd && dist < 4.0×cd && ratio > 3` | ~15/180px | 高置信度非对角接近 |
| L6 | `minDist < 0.18×cd && dist < 4.0×cd` | ~8/180px | 预测几乎确定交汇 |
| L7 | `vy > 300 && dist < 3.3×cd && dx < 1.3×cd` | ~150/60px | AI急速下落（预测不可靠） |
| L8 | `edgeDist < 0.55×cd && minDist < 0.18×cd && dist < 4.4×cd && ratio > 3` | ~25/8/200px | 垂直边缘贴近 |

> **阈值比例化（v3.4）**：所有像素阈值基于 `collisionDist`（playerHalfW + AIHalfW + 5）动态计算，角色大小变化后自动缩放。详见 `ChaseScene.BT` 配置对象。

**剩余硬编码参数（需单独关注）**：
| 参数 | 值 | 依赖 | 调整时注意 |
|------|----|------|----------|
| `L5_RATIO` / `L8_RATIO` | 3 | 长宽比（几何特性） | 与角色大小无关，无需调整 |
| `L7_VY` | 300 px/s | `PHYSICS.GRAVITY`（1200） | 重力调整时需重新校准 |
| `L4_MARGIN` | 10 px | 固定安全余量 | 不缩放，已是最小值 |
| `PREDICTION_FRAMES` | 60 帧 | 预测窗口（0.5s@120Hz） | 精度/性能平衡 |
| `PHYSICS_DT` | 1/120 s | 物理采样步长 | 精度/性能平衡 |

**关键技术**：

1. **抛物线轨迹预测**：60帧@120Hz采样（0.5秒窗口），计算玩家和AI的抛物线轨迹，返回最小预测距离（`minDist`）和垂直边缘距离（`verticalEdgeDist`）
2. **AI站平台特殊处理**：当AI站在平台上（`body.blocked.down`），不对AI施加重力，避免预测AI错误地「穿透」平台
3. **垂直边缘距离**：`|predPy - predFy| - (playerHalfH + AIHalfH)`，负值表示角色边缘重叠，用于垂直接近场景
4. **视线检测**：排除地面、NPC脚下平台（25px内），确保玩家和AI之间无遮挡
5. **闪现机制**：NPC冻结标志 + 重力禁用 + 速度清零 + 水平方向Container tween

**一次性触发**：每次追捕仅触发一次（`bulletTimeTriggered` 标记）。

### 18.3 SlowMoManager

**核心类**：`SlowMoManager`（单例，`src/game/systems/SlowMoManager.ts`，~130 行）

```typescript
// 单例获取
const slowMo = SlowMoManager.getInstance()

// 生命周期
slowMo.init(scene)    // 绑定场景，恢复 timeScale=1.0
slowMo.destroy()      // 清理，恢复全速

// 全局控制
slowMo.setTimeScale(5.0, 500)   // 0.5 秒平滑过渡到 20% 速度（1/5=0.2）
slowMo.freeze(3000)              // 冻结 3 秒（timeScale → 10000，近乎静止）
slowMo.resume(300)               // 0.3 秒恢复到全速

// 状态查询
slowMo.getCurrentScale()   // 当前 timeScale
slowMo.getState()          // 'idle' | 'frozen' | 'transitioning'
slowMo.isActive()          // 是否在慢放中

// 每帧驱动（必须在场景 update 中调用）
slowMo.update()
```

**核心原理**：
- 全局慢放：操作 `scene.physics.world.timeScale`
- 真实时间过渡：使用 `performance.now()` 驱动 easeInOutQuad 过渡，避免 timeScale 变慢后过渡也变慢
- 冻结安全值：timeScale 最大为 10000（近乎静止，不能为 0，会阻塞主循环）
- 注意：Phaser `timeScale` 语义为 `1.0 = 正常` / `2.0 = 半速` / `5.0 = 1/5 速`，即有效速度 = 1/timeScale
- 丝滑优化：等比提升 `physics.world.fps`（`newFps = baseFps × timeScale`），保持物理更新率 ≈ 60Hz，避免慢放时物体「一顿一顿」

- 再按 T → 0.3 秒恢复全速
- 可反复切换，不阻塞原有追捕逻辑

### 18.6 与现有系统的关系

| 系统 | 慢放时行为 |
|------|-----------|
| 物理引擎 | 全局受 `physics.world.timeScale` 控制 |
| 雨滴 | 自动慢放/冻结（物理体受 timeScale 影响） |
| 音效 SfxManager | 不受影响（Web Audio 独立） |
| 发音 SpeakerManager | 不受影响（Web Speech API 独立） |
| 追捕原有逻辑 | 不受影响（子弹/NPC AI/抓捕独立运行） |
